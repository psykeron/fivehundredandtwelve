<strong>Thoughts on AI-Assisted Coding</strong>
You are using AI correctly, and as long as you are using it - you aren't falling behind. You can’t turn a corner today without someone proposing a new technique or tool that you absolutely need to be using in your AI assisted coding flow - MCPs, Code Graphs, Memory Services, Context Engineering, Agentmaxxing, Loops, Graphs, Claws, Hermes, Dynamic Workflows, and on and on an on it goes. All you actually need is whatever helps you get the work done. And you keep doing that until you hit a limit, a constraint, and then you find a way to get past it. Listen to all the gurus, everything they say is valid for their context and style of work. But don’t believe that you are falling behind, or that you are not using this technology right. You are using it right. The magic of AI assisted coding is that the technology is so adaptable that we can build flows that are unique to our way of working. I learned how to use git in a dos terminal, because Windows Git UI clients were terribly slow back then. The motivation to learn it was because I felt I was losing time. Saving time was also the motivation to go from Windows (degrading filesystem performance) to Ubuntu (os failures due to driver updates) to Mac. I use Zsh, but only because I like the themes and the ability to type two letters and press the up arrow to jump to a command; I am quite sure that I am never going beyond that. I used tmux for the first time this year, because I was tired of restarting my servers in my preferred terminal layout; now that's just one bash script that launches them all in my preferred layout. The method is the same everytime. Hit a limit, or realize when you are wasting effort, and then find a way to address it. The same applies to AI tools today. You don’t need all the skills, workflows, and plugins if your experience with your harness meets your expectations.
